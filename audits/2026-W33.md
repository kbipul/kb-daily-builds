## 4. Selection-quality check — two findings, one needs a rubric change

### Finding A — the rubric has no dedup gate (**confirmed defect, act on it**)

On 2026-08-09 the selection protocol scored and *won* with `prompt-router`, an
exact concept duplicate of Day 008. The runner-up, `slm-fit-advisor`, duplicated
Day 015 `will-it-fit`. Both scored highly because nothing in the four scoring
dimensions asks "has this already shipped?" — Distinctiveness measures novelty
*against the world*, not against Bipul's own 22 repos. A dead token is the only
reason a duplicate did not go public under his name.

**Recommendation — add a hard gate, not a scoring dimension, to PLAYBOOK §1.5:**

> *Feasibility + novelty gate:* before scoring, list every shipped `repo` slug
> and one-line concept from `state.json`. Any candidate whose core mechanic
> matches a shipped project is **disqualified**, regardless of score. Record the
> dedup check in the run report.

A gate, not a penalty, because a 12/12 duplicate would still win a weighted
scheme. This is the highest-priority process change of the week.

### Finding B — format monoculture is going unpenalised (**watch, second week running**)

Counting the shipped set: `skill-scan`, `mcp-auditor`, `blast-radius`,
`will-it-fit`, `handoff-inspector`, `agent-memory-inspector`,
`contamination-scanner` — **7 of 20** are the same shape: *paste an artefact,
receive a client-side report card*. It is a good shape and it demos well, which
is exactly why the rubric keeps rewarding it: Distinctiveness is scored on
subject matter, so a seventh inspector about a new subject still scores 3.

W30's audit flagged the learning-arc question and judged it healthy. It still
is — Days 15–21 form a coherent agents arc, and Day 022 opens a credible FinOps
thread. The arc is not dissolving. What *is* drifting is format variety, and
this is now the second consecutive audit where the top-scoring picks converge on
one interaction pattern.

**Recommendation (soft, no change yet):** when scoring Distinctiveness, read the
question as *"is this a distinct thing to interact with?"* rather than *"is this
a distinct topic?"*. If W34's slate is again dominated by paste-and-report
tools, cap the pattern at one per week and re-run this note as a hard rule.

### What worked

`valueScore` calibration itself looks sound. Days 019/020 scored 12 and are the
two most substantial builds in the back half; Day 021 self-scored 10 and is
honestly the weaker of the queued pair. The scores are discriminating, not
inflated — the problem is what the rubric does not ask, not how it weighs what
it does.

## 5. Fixes applied this run

All are committed locally on top of the pending Day 022 commit. **None are on
GitHub** — the token blocks the push.

1. **Day 021 fan-out repair (from the pending commit, verified).** Backfills
   `"folder"` on every entry in `state.json`, including
   `"folder": "021-kb-agent-framework"`. This alone unblocks Day 021.
2. **`publish.yml` hardening (new this run).** The workflow now:
   - filters `status === "built"` entries that lack a usable `folder`, emits a
     `::error::` naming the offending day and repo, and **skips** them;
   - replaces the `exit 1` on a missing `project.json` with a `continue` that
     records the folder in `$SKIPPED`;
   - publishes everything healthy first, pushes `state.json`, and *only then*
     exits non-zero if anything was skipped.

   Net effect: a malformed entry is now loud and isolated instead of silently
   taking the whole day's fan-out down with it. YAML validated.
3. **Verification re-run.** Day 021: 35 tests pass, clean build, correct Pages
   `base`. Day 022: 69 tests pass, clean build. Neither needs code changes.

Nothing else was fixable — there were no typos, broken demos, or failing CI runs
in the live fleet to repair.

## 7. What Bipul has to do

**One action, two minutes, and the whole thing restarts.**

1. <https://github.com/settings/tokens> → *Generate new token (classic)*, scopes
   **`repo` + `workflow`**, no expiry (this is an unattended loop).
2. Paste into `.secrets/github_token.txt` — token only, single line.
3. **Also refresh the Actions secret `PUBLISH_TOKEN`** on `kb-daily-builds`
   (Settings → Secrets and variables → Actions). It is a sibling credential
   issued at the same time and has almost certainly expired too. The fan-out
   cannot create repos without it. *Skipping this step means the push succeeds
   and the Action still fails.*

Then either wait for the 06:00 IST run, or push the queue by hand:

```bash
cd "<workspace>"
TOKEN=$(cat .secrets/github_token.txt | tr -d '\r\n ')
git clone "https://x-access-token:${TOKEN}@github.com/kbipul/kb-daily-builds.git" /tmp/hub-recover
cd /tmp/hub-recover
git am "<workspace>/hub/RECOVERY-W33.patch"   # Day 022 + publish.yml hardening + this audit

```
