## A. The W37 fixes and the be-human rewrite never reached a single public repo *(fixed, verified live)*

**What happened.** On 14 September, commit `056b4b1` rewrote the READMEs of Days 026–034 through
the be-human pass and corrected a factual attribution in Day 031. The W37 audit separately fixed
a false claim in Day 029 and recorded it as "fixed in both places" and pushed. All of that is
true of this hub. None of it was true of the public repos.

`publish.yml` builds its work list from `state.json` entries with `status: "built"`. A project
that is already `published` is never revisited, so editing `hub/projects/NNN-*/` after publish
changes nothing a visitor can see. PLAYBOOK §3.4 says "the Action force-syncs repos", which is
half right: the Action force-pushes, but only for entries it has been re-queued to look at.

**What was live in public for six days as a result:**

| Repo | What the public copy said | What the hub had said since 14 Sep |
|---|---|---|
| `compaction-drift` (Day 031) | `policies.ts:74` and the README: "**Anthropic's** `/responses/compact`" | "**OpenAI's** `/responses/compact`" |
| `readonly-illusion` (Day 029) | `policy.ts:144`: "This is the policy the DseWiki agents **were running under**." | "the policy shape the DseWiki report describes — not a reconstruction of any real harness" |
| All nine, Days 026–034 | Pre-rewrite READMEs: 15–28 em dashes, 5–12 bold leads each | Rewritten: 4–9 em dashes, 2 bold leads each |

The two content items are the serious ones. `compaction-drift` misattributed a named product
feature to the wrong vendor, in the in-app copy of a live demo, in a series whose entire
positioning is being precise about what is known. `readonly-illusion` asserted an operational
detail of a contested third-party incident that nobody outside it can establish, which the W37
audit had already identified and believed it had retracted.

**Fix applied.** The documented re-sync path is to flip the entry's `status` back to `"built"`
and push; `publish.yml` has handled this correctly since the 2026-09-02 fix that made repo
ownership follow `folder` rather than status, and it preserves `publishedAt` while moving
`refreshedAt`. Days 026–034 were re-queued in commit `c061685`. The Action ran, force-pushed all
nine, and re-marked them published.

**Verified after the fan-out**, by cloning all nine public repos fresh:

- All nine READMEs now byte-identical to the hub.
- `OpenAI's /responses/compact` live in `compaction-drift/src/engine/policies.ts`.
- `not a reconstruction of any real harness` live in `readonly-illusion/src/engine/policy.ts`.
- Em-dash counts 4–9, bold leads 2, across all nine. Both banned series phrases gone from
  `harness-tell`.

**Process lesson, and the one change worth making.** Two audits in a row have written "fixed and
pushed" about a change that reached the hub and stopped there. PLAYBOOK §3.4 should say what is
actually required:

> Fix what's fixable immediately by editing `hub/projects/NNN-*/`, **then flip that project's
> `status` back to `"built"` in `state/state.json` so `publish.yml` re-queues it**, then push.
> An edit to an already-published project is invisible until it is re-queued. Verify by cloning
> the public repo after the Action finishes; do not verify against the hub.

Every audit should end by diffing each in-window project folder against its public repo. This
run added that check and it is what found the problem.

## B. Day 040 `last-record` — the draft expiry was wrong, and the Timeliness score rested on it *(fixed)*

README line 19 and the demo's first paragraph both read:

> The draft expires on 29 September 2026, eleven days after this build

The IETF datatracker record for `draft-sharif-agent-audit-trail-03` gives a posting date of
5 September 2026 and an expiry of 9 March 2027. Internet-Drafts run six months; 5 September plus
six months is 9 March, and the figures are self-consistent. A 29 September 2026 expiry belongs to
a version posted around 29 March 2026, which cannot be `-03`, since `-03` cites September 2026
material. The most likely explanation is that an older version's expiry was read off the
datatracker page.

This matters more than a stray date because the Day 040 rationale in `state.json` says so
directly:

> The IETF draft had not aged out in the interval, and its 29 Sep expiry raised Timeliness
> rather than lowering it.

A Timeliness 3 was awarded on a deadline that was not real. The build is still a good build and
the score would probably survive on EU AI Act Article 12 alone, which has been in force since
2 August. But the urgency the page sold to a reader was the author's, not the document's.

**Fixed** in `README.md` and `src/App.tsx`. Both now state that it is an individual submission
with no working-group adoption, that `-03` was posted 5 September 2026 and runs to 9 March 2027,
and both lead with Article 12 as the date that has actually passed. A short correction note was
added to the Build notes. 52 tests still pass; `tsc` and build clean.

**Caveat on this finding.** `datatracker.ietf.org` is outside the sandbox allowlist and returned
no response to a direct fetch. The correction rests on the search tool's read of that page. The
reasoning above is internally consistent and the six-month rule is not in doubt, but Bipul should
open the datatracker page once and confirm before treating this as closed.

## C. Day 036 `quota-commons` — two panels, two clocks *(fixed, tested)*

The committed screenshot shows, side by side at 0:11 of a 3:00 run:

- left panel, under "What each side would tell you": *"No 429s yet at this point in the run."*
- right panel, under "Run totals": fallback router, 202 sent, 81 denied, 40% denial rate.

Both were correct and they contradicted each other. `AttributionFeed`, `BudgetMeter` and
`Timeline` all take `currentT` and scope to the scrubber. `StatsTable` took
`result.consumerStats`, which is computed once for the whole run and never filtered. So the
table was answering a question the page was not asking, under a heading a reader reasonably
reads as "so far".

It undercuts this project in particular, because its thesis is that what each consumer can see
depends on where it is standing.

**Fix.** `statsUpTo(events, consumers, tSec)` added to `src/lib/simulate.ts` and exported;
`App.tsx` derives the table from it with a `useMemo`; the heading is now "Totals so far" with a
note naming the current clock position and telling the reader to scrub to the end for the full
run. Three tests added, one of which pins the defect directly:

```
it('never reports a denial before the attribution feed would show one', ...)
```

21 tests → 24, all green. `tsc` clean, build clean, smoke test at the `/quota-commons/` base
path with both dist assets returning 200 (`SMOKE_RESULT=0`). A `tsc` error caught the first
version of this fix, which is the gate doing its job.
