## Issues found & actions taken

### A. Day 033 did not publish — and the cause on file was the wrong one *(fixed, pushed)*

`ACTION-REQUIRED.md`, written at ~14:35 IST today, concluded that the `PUBLISH_TOKEN`
Actions secret had expired again, and told Bipul to regenerate a classic PAT and update the
repo secret. That was a reasonable inference from the symptoms available at the time — a
successful push followed by silence, with no way to read the Actions log from the sandbox.

**It was wrong, and I only caught it because I ran a script the playbook does not require.**

`node scripts/validate-state.mjs` — the checker W36 asked to be made a Step 4 gate, and which
is still not referenced anywhere in `PLAYBOOK.md` — fails immediately on the current state:

```
validate-state: 1 error(s) — DO NOT PUSH
  - day 33 (second-tenant): status "built" but no "folder" field —
    publish.yml WILL SKIP this project.
```

`publish.yml` filters for exactly this at line 61 and skips the entry with an
`::error::`. That single fact accounts for **every** symptom in `ACTION-REQUIRED.md`:

| Symptom | Token-expiry explanation | Missing-`folder` explanation |
|---|---|---|
| `kbipul/second-tenant` not found | ✓ | ✓ (never attempted) |
| No `chore: mark published` commit | ✓ | ✓ (nothing to mark) |
| Other repos still resolve | ✓ | ✓ |
| The local push PAT worked fine | needs two separate credentials, one dead | not involved |

The missing-`folder` explanation is strictly simpler, it is mechanically verifiable from the
repo without reading a single Actions log, and **this is the third time this exact bug has
fired** — Day 021 (2026-07-28, the original regression), Day 026 (caught in-run and fixed in
a follow-up commit, recorded in that day's rationale), and now Day 033.

**Fixed:** `"folder": "033-second-tenant"` added to the state entry — a one-line diff.
`validate-state` now reports `OK — 33 projects, dayCounter 33, 33 live repos, 0 warning(s)`.
Pushing this audit touches `state/**`, which is one of `publish.yml`'s trigger paths, so the
Action should pick Day 033 up on its own. **Bipul should not regenerate a PAT unless
`second-tenant` is still missing an hour after this push.** `ACTION-REQUIRED.md` has been
rewritten accordingly.

Two things follow from this, and the second matters more than the first:

1. **Make `validate-state.mjs` a Step 4 gate.** W36 asked for this and called it "a bug class
   that has now fired twice." It has now fired three times, and the script catches it in
   under a second. This is the single highest-value line of the four playbook edits below.
2. **A wrong diagnosis is worse than no diagnosis.** The loop reasoned confidently from
   symptoms to a conclusion it could not check, wrote that conclusion into the file that is
   also its only alarm channel, and would have cost Bipul a credential rotation he did not
   need. The honest move — which the file did make, to its credit — is that it said "this is
   inference from the symptoms, not a confirmed log line." That caveat is why this was
   recoverable. **Keep writing it.** The system-level fix is the one already on the list: an
   alarm channel that carries the actual Actions error text, so the loop stops guessing.

### B. Day 029 `readonly-illusion` — an unverifiable claim stated as fact *(fixed, pushed)*

Found by reading the committed screenshot rather than the repo, which is how W36 found its
best defect too.

Both the README and the in-app preset note read:

> This is the policy the DseWiki agents were running under.

Nobody knows that. The DseWiki incident is a **third-party claim** from the Nightingale
Collective that OpenAI has never published an account of, and several outlets covering it
state plainly that the operational details are unconfirmed. The specific egress policy a
private harness was running under is not something an external report could establish.

Why it matters more here than it would elsewhere: this project's entire value proposition
is being precise about what is known. It carries its own counterexample, it records every
rule that fires rather than just the first, and it says in the README that the corpus
"trusts its own effect labels, which assumes away the expensive part." A build that careful
should not assert a fact it cannot have.

**Fixed in both places** — README and `src/engine/policy.ts:144` now read *"the policy shape
the DseWiki report describes — not a reconstruction of any real harness."* A `## Sources`
section was added that names the claim as unverified and links both the summary and a
piece specifically on what is and is not confirmed. Crucially it also says the thing that
makes the project survive the caveat: **the 13 mechanisms are not from the incident.** Each
is a documented property of real software — MediaWiki `action=edit` over GET, `_method`
tunnelling, RFC 9110 §9.2.1 — and each row carries its own citation. The tool stands whether
or not the report holds up. Re-tested after the edit: 95 tests pass, build clean.

### The finding that matters, for the second week running

Thirty-three builds. **Zero stars. Two followers.** Re-checked this morning: sorting the
profile by stargazers returns no star counts at all, and the follower line reads "2
followers · 0 following."

Set that beside the table above. The loop correctly identified, on the day, four artefacts
that went on to accumulate over 340,000 stars between them — and then published its own
response into a room with two people in it.

That is not a scoring problem, and it is important to keep saying so. All four rubric
dimensions measure the artefact, and every one of them is doing its job: the builds
genuinely are same-day, genuinely are novel, genuinely work. **Reaching an audience is not
an artefact property, so no reweighting of artefact properties can fix it.**

W36 made exactly this recommendation and nothing changed: six weeks of LinkedIn drafts
(W30, W32, W33, W35, W36, and this one) with no evidence any was posted. Under PLAYBOOK
§3.7 — *"if either drifts two weeks running, recommend recalibrating"* — this is the second
consecutive week, so it escalates formally.

**The escalated recommendation, and it is deliberately smaller than last week's:** do not
add a scoring dimension, and do not ask Bipul to adopt a posting habit. Add **one field to
`state.json`** — `"posted": true|false` — and one line to the Monday dispatch summary
carrying the previous week's best draft ready to paste. The audit then reports the ratio.
Right now the system cannot even tell the difference between a week where Bipul posted
everything and a week where he posted nothing, which is why six audits have been able to
recommend the same thing without anything registering.

Six months to "authentic AI voice in India" started on 2026-07-08. Thirty-three public
repos at audit-grade quality is comfortably enough evidence. The bottleneck is not the
building and has not been for a month.
